# 项目交接记录

更新时间：2026-11-08（Asia/Shanghai）。这是项目文件中的长期记录，不依赖聊天上下文仍然可见。

## 一、现在做到哪里

- 产品名：一起出牌 / LAN Cards。
- 技术：Flutter 3.47.8、Dart 3.13.7；Android / iOS 原生工程；WebSocket 主机权威通信；NSD / Bonjour 自动发现。
- 当前版本：**0.3.0+3，斗地主与 21 点**。
- 已实现：三人叫抢地主、全不叫重发、17/20 张手牌、14 类牌型、合法提示、出牌与不出、炸弹 / 王炸、春天 / 反春、零和积分、结算后下一局。
- 框架能力：房间与座位、准备、原身份重连、隐藏信息过滤、断线暂停、恢复后继续、房主终止本局和踢人。
- 创建房间默认斗地主，固定三座；也可选择 2–6 人 21 点。原轮流出牌保留用于内部测试和旧版兼容，不在创建菜单展示。
- 21 点在主机结算，A 取 1 / 11，庄家软 17 停牌，仅房间积分，无下注或兑换。继承暂停、重连、空位等待和再开局。详见 `docs/blackjack.md`。
- UI：横屏首页、原创乡村背景、绿色牌桌、左右对手、叠放手牌、点击和划选、抬牌动画、暂停条与积分面板。
- 2026-10-30 源码新增隐私安全的局域网发现诊断：搜索启动、房间注册、服务无可用地址、HTTP 检查失败分阶段显示，可重试和主动复制脱敏报告。详见 `docs/discovery-diagnostics.md`；不改变游戏规则、座位或重连判定。
- 2026-11-08 参考开源斗地主实现打磨选牌体验：提示可循环切换最多 12 组候选，按点数去除花色重复，优先一手出完、普通跟牌和保留炸弹，牌桌即时显示选牌牌型及是否压得过。参考来源和取舍见 `docs/doudizhu.md`。未改房间协议或主机出牌裁决。

## 二、用户决定，不要重新误解

1. 面向朋友外出：大家各持一部手机，Android / iPhone 均兼容，尽量降低加入门槛。
2. 所有人安装 App 优先；网页端不是当前目标。
3. 已经连接同一个 Wi-Fi 或某人的手机热点即可。不要求首版自动建热点，也不要求存在互联网。
4. 首页两个主按钮：创建房间、搜索房间。点列表加入；IP 输入只能是找不到房间时的备用入口。
5. 每设备一个房间，每房间同时一局。房主设备内运行主机，不用外部服务器。
6. 不投入复杂后台保活，只提示用户尽量保持前台；前台保持亮屏不是后台执行权限。
7. 曾讨论过 69 秒倒计时，但用户已明确取消。不要重新加上自动超时处罚。
8. 离线身份保留座位，不能被新人顶替。App 再打开自动尝试认领原座位，不把“连接断了”当作“主动退出”。
9. 当前局参与者离线则暂停；全员恢复和同步后自动继续，无需房主再确认。
10. 房主可继续等待或结束当前局。结束本局作废、不计分，在线玩家仍在原房间，离线座位也保留；只有手动踢人 / 主动退出 / 房间关闭释放座位。
11. 房主进程结束，旧房间就结束。其他人自行新开房间，不做主机迁移或磁盘恢复旧局。
12. 新人可坐空位，但当前手已经开始则等下一手。斗地主三座已满时自然不能加入新人。
13. 首版先基础框架，后来用户明确要求接入斗地主、横屏、抢地主，允许网上找美术或原创生成。
14. 视觉灵感可以参考休闲斗地主，不复制《欢乐斗地主》的现有资源；用户尚未给当前美术提出具体返工意见。

## 三、斗地主规则的关键细节

- 先叫 / 不叫；出现叫地主后，未“不叫”的其他人依次抢 / 不抢。有人抢时，最初叫地主者有最后一次反抢。
- 每次抢地主倍数 ×2；底分 1，炸弹 / 王炸 ×2，春天 / 反春 ×2。
- 地主拿 3 张底牌并先出，底牌此时向全员公开；确定地主之前不泄露底牌。
- 地主赢一方，两名农民共同构成另一方；地主输赢两份，农民各一份，单局积分之和为零。
- 单翅膀、四带二等存在民间变体，当前具体选择已写在 `docs/doudizhu.md`，不要默默换规则。
- 叫抢阶段退出 / 被踢出作废；地主确定后，退出者所在阵营弃权，不算春天。这和“房主手动终止本局一律不计分”是不同动作。
- 主机重新发牌时更新 roundId；旧局操作不能作用于新局。
- supportedGames 握手检查阻止旧客户端误入不支持的斗地主房间；旧版未带能力字段的客户端只兼容轮流出牌测试房间。

## 七、开发环境与已解决的坑

- 当前 Windows 工具安装在用户的 `.codex/cache/`，没有改系统 PATH；`tool/dev.ps1` 会自动找到本机缓存的 Flutter / JDK / Android SDK。
- 开发脚本会建立临时 ASCII 盘符，正常结束后撤销映射，不移动工程。脚本被强行中断时可能残留映射，应确认归属后仅撤销映射，不删除项目目录。
- Windows 项目和 Pub 缓存盘符不同曾导致 Kotlin 增量缓存 different roots 错误；`android/gradle.properties` 已关闭 Kotlin 增量缓存。
- 某 Flutter 版本在中文目录调用 flutter analyze 有 LSP 编码问题，可用 `dart analyze --format machine lib test tool`。
- 通过临时盘符跑过检查后，Flutter native-assets hooks 可能缓存该盘符的路径；撤销映射后直接从中文原路径运行测试曾报找不到 `P:\`。用 `tool/dev.ps1 check` 重新映射并解析依赖后检查通过，不要将工具缓存错误归为发现或真机兼容性失败。
- WebSocket sink 可以先于 readyState / onDone 关闭，发送路径已防护；新连接替换旧连接时，旧连接回调不能把新连接标记离线。
- Widget 测试的默认阴影模式不同于真实渲染，预览工具临时启用真实阴影并在测试体返回前恢复，避免框架不变量检查失败。
- 不直接信任 Kimi 初稿：已修复负边距叠牌、局部准备状态、结束不能再准备、暂停挡住房主控制等问题。
- 发现诊断采用内存中的固定枚举和计数，不保存端点、服务 / TXT、房间 / 玩家信息、原始异常或 HTTP 响应体。只有用户主动点击才复制脱敏报告，无自动日志、保存或上传。
- NSD 关闭插件自动解析，由发现服务显式解析，才能显示已发现但解析失败 / 无可用地址的情况。原生接口可注入测试替身；HTTP 故障分类使用真实本机 Socket 测试。停止搜索后忽略旧结果，发布失败独立于可被普通操作清空的 UI 消息。
